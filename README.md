# 📦 재고관리

폰으로 찍은 제품 사진을 올려 재고를 등록하고, 판매·수익까지 한 화면에서 보는 웹앱.

## 🔗 주소

**<https://j93100114-commits.github.io/boseongwon-calendarm/>**

### 📱 폰에 앱으로 설치하기

1. 폰 브라우저로 위 주소를 엽니다.
2. **안드로이드(크롬)** — 주소창 오른쪽 **⋮** → `앱 설치` 또는 `홈 화면에 추가`
   **아이폰(사파리)** — 아래 **공유 버튼** → `홈 화면에 추가`
3. 홈 화면에 📦 아이콘이 생기고, 누르면 주소창 없이 앱처럼 열립니다.

> ⚠️ **`index.html` 파일을 폰에 직접 옮기면 안 됩니다.** `file://` 로 열면 홈 화면에 추가해도
> 앱이 아니라 북마크가 되고, Firebase 가 막혀(출처가 `null`) 재고가 하나도 안 뜹니다.
> 반드시 위 **https 주소**로 여세요.

### 코드를 고친 뒤 반영하기

```bash
git add -A && git commit -m "수정 내용" && git push
```

1~2분 뒤 사이트에 반영됩니다. 서비스워커가 **'먼저 인터넷, 안 되면 담아둔 것'** 방식이라
폰에 옛 화면이 남지 않습니다 (파일 이름에 `?v=…` 를 붙일 필요가 없습니다).

| 항목 | 뜻 |
|---|---|
| 💵 실판매가 | 실제로 파는 값 |
| 🏷️ 원래가격 | 정가 (할인율 표시에 씀) |
| 🔨 경매가격 | 낙찰받은 값 = **기본 원가** |
| 📦 개수 | 재고 수량 |
| 📅 입고날짜 | 물건이 들어온 날 |

**수익 = 실판매가 − 원가**. 원가를 무엇으로 볼지는 화면 위의 `💡 수익 계산 원가 기준` 칩(또는 ⚙️ 설정 탭)에서 언제든 바꿀 수 있습니다. 기본은 **경매가격**입니다.

## ☁️ 클라우드 연결 (폰 ↔ PC 같이 쓰기)

기존 프로젝트 **`jangggimaster`** 를 같이 씁니다. **세 줄만 채우면 끝**입니다. 2분.

### 1. 설정값 세 개 복사

<https://console.firebase.google.com/u/0/project/jangggimaster/settings/general> 을 열고
맨 아래 **내 앱** 칸을 봅니다.

- 웹 앱(`</>`)이 **이미 있으면** → **SDK 설정 및 구성 → 구성** 을 누릅니다.
- 웹 앱이 **없으면** → **앱 추가 → 웹(`</>`)** → 닉네임 아무거나(예: 재고관리) → 등록.
  (Firebase 호스팅 설정은 체크 안 해도 됩니다)

그러면 이런 코드가 나옵니다.

```js
const firebaseConfig = {
  apiKey: "AIza...",                    // ← 이거
  authDomain: "jangggimaster.firebaseapp.com",
  projectId: "jangggimaster",
  storageBucket: "jangggimaster.firebasestorage.app",
  messagingSenderId: "123456789012",    // ← 이거
  appId: "1:123456789012:web:abc..."    // ← 이거
};
```

### 2. config.js 에 붙여넣기

이 폴더의 **`config.js`** 를 열면 `apiKey` · `messagingSenderId` · `appId` 세 줄이 비어 있습니다.
거기에 채워 넣고 저장하세요. 나머지 세 줄은 이미 채워져 있으니 그대로 두면 됩니다.

### 3. 규칙(Rules)은? — 손댈 것 없습니다 ✅

`jangggimaster` 에 지금 걸려 있는 규칙이 이것입니다.

```
match /{document=**} {
  allow read, write: if true;
}
```

`/{document=**}` 는 **모든 컬렉션**이라는 뜻이라, 이 앱이 새로 만들 세 컬렉션도 이미 허용됩니다.
콘솔에서 규칙을 다시 게시할 필요가 없습니다.

- 로그인도 켤 필요 없습니다. `config.js` 의 `USE_ANON_AUTH` 가 `false` 라 앱이 로그인 없이 바로 붙습니다.
- Firestore Database 도 이미 만들어져 있으니 그대로 씁니다.

### 4. 확인

`index.html` 을 새로고침 → 오른쪽 위 배지가 **☁️ 클라우드 연결됨** 으로 바뀌면 끝입니다.

## 🤝 기존 데이터와 섞이지 않나?

안 섞입니다. 이 앱은 **새 컬렉션 세 개만** 만들고 다른 곳은 건드리지 않습니다.

| 컬렉션 | 무엇 |
|---|---|
| `inventory_items` | 제품 정보 + 목록용 작은 사진 |
| `inventory_photos` | 원본 사진 |
| `inventory_sales` | 판매 이력 |

이름을 바꾸고 싶으면 `config.js` 의 `COL_ITEMS` · `COL_PHOTOS` · `COL_SALES` 를 고치세요.

> ⚠️ 규칙이 `if true` 라는 건 **프로젝트 ID 를 아는 사람이면 누구나 읽고 지울 수 있다**는 뜻입니다.
> 프로젝트 ID 와 apiKey 는 브라우저에 그대로 보이므로 숨겨지지 않습니다.
> 지금은 그대로 쓰기로 했고, 나중에 잠그고 싶어지면 `firestore.rules` 파일 아래쪽에
> 잠그는 방법(익명 로그인 + 규칙)을 적어 두었습니다.

## 💾 사진은 어떻게 저장되나

파이어베이스 **스토리지(유료 플랜 필요)를 쓰지 않습니다.** 대신 사진을 줄여서 Firestore 에 글자로 담습니다.

| | 크기 | 어디에 | 언제 읽나 |
|---|---|---|---|
| 목록용 작은 사진 | 긴 변 400px · 약 20~40KB | 제품 문서 안 | 목록을 볼 때 |
| 원본 사진 | 긴 변 1280px · 약 150~400KB | 별도 문서(`inventory_photos`) | **제품을 눌러 상세를 열 때만** |

원본을 따로 떼어 둔 덕분에 목록을 넘길 때 사진 데이터가 딸려오지 않습니다.
화질을 바꾸려면 `config.js` 의 `PHOTO_MAX_SIDE` · `PHOTO_QUALITY` 를 조정하세요.

- 폰 사진이 옆으로 눕는 문제(EXIF 방향)는 `createImageBitmap` 으로 바로잡아 저장합니다.
- Firestore 문서 하나는 **1MB** 를 넘을 수 없습니다. 글자로 바꾸면 약 1.33배 불어나므로
  원본은 700KB 아래로 유지해야 합니다. 기본값은 충분히 안전합니다.

### 무료 한도

Firestore 무료(Spark) 요금제 기준 저장용량 1GiB · 하루 읽기 5만 건.
사진 한 장을 약 400KB로 보면 **2,000장 남짓**까지 무료 범위입니다.

읽기를 아끼려고 앱은 이렇게 동작합니다.
- 화면을 열 때 **한 번만** 읽습니다(실시간 구독 없음). 다른 기기에서 바꾼 것은 **🔄 새로고침**으로 가져옵니다.
- 등록·수정·판매 후에는 서버를 다시 읽지 않고 화면의 값만 고칩니다.
- 원본 사진은 상세를 열 때만 1건 읽습니다.
- 한 번에 최대 500개까지 불러옵니다 (`config.js` 의 `LOAD_LIMIT_ITEMS`).

## ⚠️ 알아둘 것

- **로그인이 없고 규칙도 열려 있습니다.** 주소와 프로젝트 ID 를 아는 사람은 들여다볼 수 있으니,
  개인정보처럼 정말 잠가야 하는 자료는 넣지 마세요.
  잠그고 싶어지면 `firestore.rules` 아래쪽에 방법을 적어 뒀습니다 (또는 말씀해 주세요).
- **판매 이력의 수익은 팔던 시점의 원가로 굳습니다.** 나중에 원가 기준을 바꿔도 지난 기록은 그대로입니다.
- **판매 [취소]** 를 누르면 재고가 그만큼 되돌아옵니다. 제품이 이미 삭제됐으면 기록만 지웁니다.
- 로컬 모드의 데이터는 브라우저 저장소(IndexedDB)에 있습니다. **브라우저 데이터를 지우면 함께 사라집니다.**
